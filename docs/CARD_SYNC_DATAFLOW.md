# 闯关学习与卡片学习数据流集成

## 概述

本项目实现了闯关学习和卡片复习系统之间的自动数据同步，让用户在闯关学习中的表现能够自动转化为复习卡片，形成完整的学习闭环。

## 数据流架构

```
闯关学习 → 挑战答题 → 自动同步 → 卡片系统 → 复习学习
```

## 核心功能

### 1. 自动同步机制

当用户在闯关学习中完成挑战时，系统会自动：

- **答对情况**：
  - 创建/更新卡片，设置较低难度（难度系数：3）
  - 安排在1天后复习
  - 标记为"新学习"状态

- **答错情况情况**：
  - 创建/更新卡片，设置较高难度（难度系数：7）
  - 立即安排复习
  - 重置为"学习中"状态
  - 记录失误次数

### 2. 智能卡片解析

系统会自动解析挑战内容，提取单词和翻译：

```
挑战问题: "请选择 'apple' 的中文含义"
正确答案: "苹果"

解析结果:
- 单词: apple
- 翻译: 苹果
- 标签: ["闯关学习", "自动添加"]
```

### 3. 手动同步功能

用户可以主动将整个课程的所有挑战同步到卡片系统：

```typescript
await syncLessonToCards({
  userId: "user-123",
  lessonId: 1
});
```

## 技术实现

### 核心文件

1. **[actions/card-sync.ts](actions/card-sync.ts)** - 同步逻辑
   - `syncChallengeToCard()` - 单个挑战同步
   - `syncLessonToCards()` - 批量课程同步
   - `getSyncedCardsStats()` - 获取同步统计
   - `clearSyncedCards()` - 清除同步卡片

2. **[actions/learning-progress.ts](actions/learning-progress.ts)** - 学习进度追踪
   - 集成卡片同步功能
   - 答题后自动触发同步

3. **[components/sync-status.tsx](components/sync-status.tsx)** - 状态显示组件
   - 显示同步卡片数量
   - 显示待复习数量
   - 提供手动同步按钮

4. **API Endpoints**:
   - `POST /api/sync-lesson` - 手动同步课程
   - `GET /api/sync-stats` - 获取同步统计

### 数据库集成

使用以下表结构：

- `cards` - 卡片定义表
- `user_card_progress` - 用户卡片进度（包含FSRS状态）
- `challenges` - 闯关挑战表
- `challenge_options` - 挑战选项表

## FSRS 算法集成

卡片系统使用 FSRS (Free Spaced Repetition Scheduler) 算法：

- **状态机**: new → learning → review → relearning
- **动态调度**: 根据用户表现调整复习间隔
- **难度计算**: 结合卡片固有难度和用户表现

## 使用示例

### 自动同步（推荐）

用户只需正常进行闯关学习，系统会自动处理：

```typescript
// 用户答题后
const result = await updateChallengeProgress({
  userId: "user-123",
  challengeId: 1,
  isCorrect: false,  // 答错了
  timeSpent: 3000
});

// 系统会自动：
// 1. 更新挑战进度
// 2. 创建/更新卡片
// 3. 设置立即复习
```

### 手动同步

用户可以主动添加课程到卡片系统：

```typescript
const result = await syncLessonToCards({
  userId: "user-123",
  lessonId: 1
});

// result: { success: true, syncedCount: 10, existingCount: 5, total: 15 }
```

### 查看同步状态

```typescript
const stats = await getSyncedCardsStats("user-123");

// stats: { total: 15, due: 3, cards: [...] }
```

## 性能考虑

- **异步处理**：同步操作异步执行，不影响用户体验
- **批量操作**：支持批量同步，减少数据库操作
- **缓存机制**：使用 React cache 减少重复查询
- **索引优化**：关键字段建立数据库索引

## 故障处理

- **网络错误**：同步失败不影响正常学习
- **数据冲突**：重复卡片会更新而非重复创建
- **状态恢复**：系统可以检测并修复不一致状态
